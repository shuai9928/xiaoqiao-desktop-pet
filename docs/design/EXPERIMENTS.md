# 实验记录(避免重复做已经失败的实验)

每条记录:目的 → 原始行为 → 修改 → 结果 → 决定。

## 已保留的实验

### E1 · 音效 5 秒全局限频(R15)
- 假设:连点/靠近时多音效叠加太吵,单一冷却不够。
- 修改:SFX.GLOBAL_CD 0.06 → 5.0,被限频的请求直接丢弃。
- 结果:用户确认吵闹问题消失。**保留**。

### E2 · 音效"最新胜出"打断(R15)
- 原始:允许多音效叠放(仅施法闪烁为合法叠层)。
- 修改:main 槽位新声音立刻 close 上一条;fx 槽(施法闪烁)例外。
- 结果:任何时刻只有一条主声音。**保留**。

### E3 · 贴纸分类系统对齐(R27)
- 发现:throw 用了 emotions.json 里不存在的 "shocked" 分类,贴纸静默失效;
  angry/thanks 分类从未触发。
- 修改:throw → "surprised";眩晕随机掺 "angry";吃糖完成补 "thanks"。
- 结果:全量对照审计清零。**保留**。

### E4 · 环境星光稀疏与星光值联动(R26)
- 假设:能量低时周围星星变稀,和饥饿台词构成双重信号。
- 修改:环境星光间隔 × (1 + (1-star/100)×1.5)。
- 量化:满星光 0.778s vs 零星光 1.945s;满星光行为与原版一致。**保留**。

### E5 · 连摸彩蛋 + 久别重逢台词(R25)
- 假设:高频互动需要递进反馈;久别唤醒值得特殊台词。
- 结果:6 秒摸 6 次触发"融化"(60 秒冷却);睡着 10 分钟以上被摸头说
  重逢台词。**保留**。

### E6 · 预乘取字节单趟化(R30)
- 原始:`_push`/`push_layered` 每帧做 3 次 `ImageChops.multiply` + merge
  再 `tobytes("raw","BGRA")`。
- 修改:合并成 `premult_bgra()` —— `convert("RGBa")` 单趟 C 预乘 +
  bytearray 切片换 R/B。实测 645x780:7.77→5.21ms/帧;967x1170:
  12.99→11.23ms/帧。
- 结果:与旧实现逐字节比仅 0.9% 的中间 alpha 像素差 ±1 舍入,肉眼
  不可见(alpha 通道完全一致)。**保留**。

### E7 · 推帧 GDI 资源池(R31)
- 原始:每帧 GetDC + CreateCompatibleDC + CreateDIBSection +
  SelectObject/DeleteObject 全套重建(两个推帧路径都是)。
- 修改:按尺寸缓存常驻 屏幕DC+内存DC+DIB(`_gdi_surface`,池 ≤4,FIFO),
  每帧只 memmove。
- 结果:实弹施放全屏魔法与日常运行零推帧失败(_push_debug.log 无新条目)。
  顺带修掉 `push_layered` 漏 BGRA 参数导致的红蓝对调。**保留**。

### E8 · 睡眠遮罩/贴纸淡出缓存(未采纳)
- 假设:睡眠时每帧 `Image.new` 全画布遮罩、贴纸淡出每帧 copy+point
  可以缓存。
- 实测:睡眠呼吸的 alpha 持续振荡,按值缓存要 13 张全画布(≈100MB),
  copy+putalpha(3.19ms)反而比 Image.new(2.38ms)慢;贴纸淡出实测仅
  0.22ms(point 是查表实现)。
- 决定:**放弃**,现状已是最优,不要重复尝试。

### E9 · 粒子精灵库备料(fx.ParticleSprites,已备料、未接入)
- 目的:render 粒子段(pet.py:5425-5587)每帧逐颗 polygon/ellipse,按
  fx.py"预渲染精灵"的老路线备料,用数据验证接入值不值。
- 修改:fx.py 末尾追加 ParticleSprites —— 旋转 24 档 / alpha 8 档 /
  尺寸 2px 档量化,LRU 320 上限,alpha 档从基准图派生,"1" 模式二值
  掩码整像素替换;新增 _test_fx_particles.py(视觉等价 20 组全过 /
  缓存有界 / 性能三场景)。
- 结果:等价性成立 —— 掩码替换与直画逐字节一致。两个实测才知道的坑:
  ① pet.py 粒子是**覆写**不是混合(Draw(im,"RGBA") 在 RGBA 目标上连
  alpha 一起替换),精灵 paste 必须用二值掩码,拿精灵自身当掩码会变成
  source-over(RGB 预乘、alpha 平方),能量对不上;② 掩码要用 "1" 模式
  (L 掩码逐像素混合,比直画还慢 3 倍)。全命中单发:heart(26 点)
  x2.72、star x1.30、cstar x1.23、sparkle x1.15;petal/leaf/confetti/
  snow/firefly 贴图反而 x0.5~0.8(4 点多边形和椭圆直画近乎免费);
  独参 churn 场景 x0.25(自转档位穿越逼着重画,量化缓存最怕这个)。
- 决定:**只值得接入 heart**(不旋转所以无档位穿越、命中稳、x2.7),
  其余 kind 的直画已近最优,不接入。备料库和测试保留作基础设施;
  接入时按 _test_fx_particles.py 场景 (c) 的数据逐 kind 决策,不要凭
  "预渲染一定快"的惯性整段上。

### E10 · 动作特效补全:gear/dial 粒子 + 六动作接线(R32)
- 目的:挥手/打滚/伸懒腰/摔跤/睡醒/挠痒痒只有动作没有特效,画面单调。
- 修改:粒子系统新增 `gear`(金色小齿轮:齿圈+辐条+轴心,会转)和
  `dial`(悬在头顶的表盘虚影,指针**倒着走**=时间倒流的意象)两种,
  走现有 add_part 管线程序性直画(和 star/heart 同一套,按 E9 的实测
  直画已近最优,单帧峰值 ≤8 个多边形,无新预渲染设施)。接线:挥手=
  每挥拍洒时之沙+收手飘齿轮;打滚=时之沙尾迹(0.14s 节流)+站起表盘;
  伸懒腰=弓顶表盘浮现+卸力碎成时之沙;摔跤=坐地扬尘+两颗齿轮弹走;
  睡醒=表盘化开(和入睡的 zzz 呼应);挠痒痒=笑抖时之沙。
- 踩坑:粒子 y 是**相对窗口中心的坐标**,头顶只到 ≈ -0.26H;第一版
  用了 -0.5H 以下,全画到画布外看不见。调特效位置先用
  `add_part(...) → render() → _frame_buf.save()` 无头渲染一张确认,
  比掐秒截屏可靠(截屏往返 2~3s,追不上 1s 寿命的粒子)。
- 追加(R33,第二批):哈欠=两枚小 zzz 前奏(比睡着的更小更慢);被冷落
  撒娇=两三滴小泪珠;猜拳平局=一颗"叮"的时之沙、输了=跺脚冒泪珠;
  靠近问候=身边惊起两三粒星尘;戳脸=戳中位置弹开两粒小星;12:34 彩蛋
  =三颗小齿轮排成一列从她面前正步走过(替"数字们"出场)。
- 结果:69/69 回归全绿,实弹触发全程 pet_error.log 零异常。**保留**。

### E12 · 安静待机 20fps 档(R34)
- 假设:待机时画面上只有呼吸浮动(±3.5px/2s)和氛围粒子,20fps 与
  30fps 肉眼无差别;且旧逻辑"有粒子就 60fps"让常驻的环境星光把待机
  一直拽在 60fps 档。
- 修改:粒子分两类的帧率语义 —— AMBIENT_PARTS(zzz/雪/花瓣/落叶/萤火/
  星光)不再触发 60fps;新增第四档:idle + 无气泡/贴纸/法阵/思考/嘴型/
  蹦跳/眨眼 + 4 秒无互动 + 光标远离 → 50ms(20fps),任何信号变化下一帧
  立即回 30fps。判定抽成 _quiet_idle_ok(),state 文件(--debug-state)
  会报 quiet_idle/quiet_block 方便核对。
- 顺带修掉:气泡过期从不清 None(渲染只是不画它),残留气泡会把降帧
  判定永久挡住 —— 说过一次梦话后连睡眠 10fps 档都会失效,是既有 bug。
- 结果:对照实测(各 6×8s 采样取最小)待机 CPU 32% → 18%。回归
  72/72。**保留**。

### E13 · 预乘域降采样 + 预乘取字节单行化(2026-09-15)
- 原始:2x 画布 `frame.reduce(2)` 后 `premult_bgra` 推帧。剖析发现 PIL 的
  reduce 对 RGBA 内部就要先预乘、缩完再还原,推帧时又预乘一次 —— 每帧
  "预乘→还原→再预乘",中间两趟整帧转换白做;`premult_bgra` 还用
  bytearray 切片手工对调 R/B(注释以为 Pillow 没有 BGRa packer,其实有)。
- 修改:`frame.convert("RGBa").reduce(SS)` 直接在预乘域缩;`premult_bgra`
  改为 RGBa 输入直接 `tobytes("raw", "BGRa")`。
- 结果:推帧管线 1290x1560 源 10.03 → 6.67ms/帧,逐字节误差 ≤1、alpha 完全
  一致;`premult_bgra` 3.64 → 2.08ms 且逐字节相同。**保留**。

### E14 · 帧节奏补偿(2026-09-15)
- 原始:tick 干完活再固定 `after(_frame_delay())`,渲染耗时被叠加进间隔。
  跳舞一帧画 36ms,标称 30fps 实测 13fps;`_tick_body` 的 dt 上限 50ms,
  帧间隔超过它时按时间推进的动作还会变慢动作。
- 修改:新增 `_paced_delay(spent)` = max(4, 目标间隔 - 本帧耗时);
  `_frame_delay` 语义不变,原有档位断言不受影响。
- 结果:跳舞 13.0 → 21.1fps、常规待机 18.3 → 26.4fps(更接近设计值)。
  帧数变多会抬高 CPU,但与 E13/E15/E16 合计后,真实挂机单核
  31.2% → 18.7%。回归用例 3.87。**保留**。

### E15 · 地面法阵静态层预合成(2026-09-15)
- 原始:光垫 + 四道环都不转,每帧仍分 5 次带蒙版 paste(待机每帧约 2ms)。
- 修改:`fx._merge_mask_layers` 按 paste 的蒙版插值语义精确预合成
  (颜色 C=P/M、覆盖率 M=1-∏(1-m)),运行时只贴 1 次。
- 结果:1.03 → 0.45ms,中心为整数时误差 ≤3;非整数中心有 1 个超采样
  像素的整体平移(输出 0.5px)。**保留**。
- **教训**:第一版用 numpy 算,结果 pet 进程私有提交内存 215 → 696MB ——
  pet 原本完全不加载 numpy,而 numpy 背后的 OpenBLAS 在 16 核机器上一
  import 就预留约 490MB 线程缓冲。改为纯 PIL(ImageMath 逐通道)后
  回到 192MB。`test_pet.py` 加了"运行时不加载 numpy"防线。

### E16 · 被动 AI 检查不再同步导入 genai(2026-09-15)
- 原始:`brain.available` 首次访问会当场 import google.genai(约 0.8 秒)。
  第一帧 tick 的主动搭话检查就访问了它,把开机 25 秒后台预热抵消了。
- 修改:`AIBrain.ready`(SDK 未加载直接 False)+ `Pet._ai_ready()`;闲聊
  事件、主动搭话、调试状态三处被动检查改用它,互动路径仍用 available。
- 结果:首帧前 1358 → 516ms,`Pet(root)` 1149 → 299ms。**保留**。

### E17 · 变形源图预乘缓存(2026-09-15)
- 原始:PIL 对 RGBA 做 MESH 变换时每次把整张源图转 RGBa、变完再转回;
  跳舞时变形缓存几乎不命中,每帧都付这两趟转换。
- 修改:`DepthWarp._premultiplied` 缓存 lit_source 那几张长寿源图的 RGBa
  版(按对象身份,≤3 条),变换后只转回一次;临时五官贴图照常直接转换。
- 结果:4 组姿势输出与原实现逐字节相同;单次未命中变形 23.35 → 21.68ms。
  **保留**。

### E19 · 动作打磨:落脚 / 晕眩 / 挥手(2026-09-16)
- **落脚**:走路原来每 0.35 秒固定洒一粒 3~5px 星尘,和真实位移脱节。
  现在按步相(走过的距离)在整数处落脚,同时做三件事:squash 压到 0.955
  踩实、脚边扬 2~3 粒 5~8.5px 星尘往身后甩、`_step_flash` 记一下时刻,
  渲染侧据此给脚下法阵一个 0.18 秒、峰值 0.38 的能量脉冲(踩亮五芒星)。
- 试过但**弃用**的两种落脚光环:①`self.circles` 的小魔法阵 —— 它恒定
  画在身体正中,和常驻地面法阵完全重叠,等于没画;②`_shocks` 冲击波
  (strength 0.13)—— 起始几帧半径太小,看着是一团紫斑不像脚步。
- **晕眩**:补了一圈绕头顶转的星星(0.07s 一颗,`dizzy_amp>0.18` 时才发)。
  第一版锚在 `-0.42H`,那是气泡的高度,飘在帽子上方老远;改到 `-0.28H`、
  半径 `0.24W`、并跟着 `lean` 一起歪,才像绕着她转。
- **挥手**:原来 lean 只有 ±0.065(约 4°),四帧连拍分辨不出她在动。
  提到 ±0.115,并加一条 `_spin_lift` 轨道每拍踮脚 3~5px、squash 跟着脉冲。
- **吃糖**:糖 1.1 秒进嘴到 2.2 秒结算之间什么都不发生。进嘴那拍从嘴角
  迸 5 粒金屑,之后每口嚼(1.24/1.52/1.8,对上压扁拍)再崩 2 粒;节拍用
  `_eat_beats` 集合记,掉帧不重放不漏。嘴的位置由渲染侧记到 `_mouth_xy`。
  第一版碎屑是白/浅金、速度小,正好落在白领口和脸上,原尺寸都看不见;
  改成 GOLD/GOLD_L 往两侧甩出轮廓。咀嚼 squash 想加到 0.955,但
  `test_action_fx` 给吃糖定了 [0.96, 1.04] 的防变形边界,守住边界。
- 冥想重拍后确认没问题(1.5 秒起明显离地),之前"看不出浮空"也是下落帧。
- **审查工具的坑(重要)**:`shoot_actions.py` 起的沙箱小乔会沿用存档里的
  `fy`,若高于地面就一路慢慢飘下来 —— 重力兜底把 walk/dizzy 等常规状态
  全转成 `fall`,**这之前拍的动作对照图有一批其实是下落帧**。现在建实例
  后立刻 `p.fy = float(p.ground_feet)`;另外她可能贴着屏幕边缘,walk 要
  朝有空间的一侧走,否则 `walk_target` 被夹成原地、动作一触发就结束。
- 回归:`test_pet.py` 新增"落脚点亮法阵""挥手摆幅""晕眩中段转星星"四条(含吃糖),
  114/114 通过。


### E20 · 待机法阵:呼吸光 + 光纹(2026-09-17)
- 原始:待机时整只唯一在动的是 ±3.5px 的上下浮动;脚下法阵只有符文匀速转,
  光垫亮度是死的。
- 修改:`fx.FX._build_living` 预渲染 8 档呼吸光(压扁柔光饼)和 14 档光纹环;
  `ground_circle(..., breath=)` 在静态层与符文之间贴呼吸光,亮度与浮动同相
  (浮到高处最亮,第 0 档直接跳过不贴);render 里每 5.2 秒从金色内圈荡出
  一道光纹,1.8 秒走到外圈,按全局时钟算,不存状态、不产粒子。
- 第一版**看不出来**(截图改前改后几乎一样):呼吸光垫在静态层底下,被光垫
  那张 105 透明度的圆饼盖掉六成;光纹是 1~2px 淡蓝细线、不带泛光,和法阵
  自己的环同色同粗。实测修正后法阵中心亮度 91.8 ↔ 117.2(L 通道)。
- 成本(逐帧交替 A/B,只计 render,各 400 帧):待机中位 +0.21 / +0.20ms,
  配对差中位 +0.26 / +0.12ms。单调用:呼吸光 0.15ms(scale 1.0)/0.23ms
  (1.25),光纹 0.09/0.13ms 且只占 35% 的时间。帧率档不变(test_pet 用例)。
- **剖析口径的坑**:15 秒 cProfile 在这台机器上同一份代码两次能差 3ms
  (连续跑时热降频漂移,4 组交替 A/B 的差值从 -0.65 到 +2.41ms),分辨不出
  亚毫秒增量;cProfile 还会放大新增的几层 Python 调用,并让所有演出动作都
  超出 13ms 快档预算、全程停在 30fps。判断"待机 +≤1ms"要用逐帧交替 A/B
  (scratchpad `bench_render.py` 的做法),不要拿两次独立剖析相减。
  **保留**。

### E21 · 命中光环 hit_ring(2026-09-17)
- 原始:摸头/挠痒/接星/喂糖的反馈全是会飘走的粒子,点中的那一下没有落点;
  接星只洒一粒 6~10px 的 sparkle。
- 修改:新粒子 kind `hit_ring`(寿命 0.38s),渲染时按进度贴 `fx.hit` 的
  10 档预渲染精灵(亮芯 + 收尖四角星芒 + ease-out 扩散环);`on_release`
  记下点击位置,`_click_rel` 取不到新鲜点击(聊天/指令触发)时落回头顶。
  摸头与融化彩蛋用粉色,挠痒/接星/喂糖结算用金色,接星连击错开 0.09s
  再荡一圈。**不进 AMBIENT_PARTS**:它是互动瞬间的演出,在场时允许顶到
  60fps,寿命到了清掉即回安静档。
- 第一版的星芒是等粗十字细线、环不带柔光,深色底上像瞄准镜准星;深粉在
  尾段低透明度时发灰发棕。改成菱形星芒 + 泛光环 + 亮粉,淡出放慢
  (0.2 秒时仍清晰)。
- 预渲染:第一版每档一律开最大画布(260px)做 3~4 次全尺寸高斯,20 张用掉
  81ms 启动时间;改为每档按需开画布 + 柔光层半分辨率模糊,降到 48ms。
- 成本:单调用 0.12/0.18ms;光环在场时 render 配对差 +0.39ms。**保留**。

### E22 · 蹦跳重做:整数个抛物线小跳 + 触地压扁(2026-09-17)
- 原始:`bob = -abs(sin(16t)) * (5 + hop_t*10)`,t 是全局时钟。三个毛病
  (按 30fps 采样画曲线确认):①起跳那帧常在半空(例:相位落在 0.07s 时
  第一帧就离地约 12px,凭空瞬移);②hop_t 归零那帧也在半空,直接掉回地面;
  ③abs(sin) 的谷底按 30fps 采样几乎踩不到 0,中间几跳根本没落地。起跳设
  一次 squash 0.9,之后触地不再压扁。
- 修改:`hop()` 把时长凑成 0.07s 蹲 + 整数个 0.2s 小跳;`_hop_curve` 每跳
  一条抛物线、一跳比一跳低(峰值仍是 5+10×力度);`_hop_touchdown` 按跨过
  的触地时刻判断(10/20/30/60fps 次数一致),触地时 squash 压到 0.93。
  呼吸浮动不停,小跳叠加在上面,起落都不跳变。hop_t 仍是剩余秒数,其他
  地方 `hop_t > 0` 的语义不变。
- 踩坑:起跳那一帧 (prev-蹲) 为负,地板除得 -1,会把起跳误数成触地 ——
  帧率无关用例在 10fps 下数出 5 次触地才发现。
- **砍掉的部分**:空中拉伸(squash +0.045)。变形缓存键是
  `round(render_squash*12)`,一档 0.083,±0.045 跨不过档位边界,画出来和
  没拉一样;拉到能跨档(>0.042 且叠加回弹中的 squash)会显得像橡皮,还要
  多一张网格。触地的 0.93 恰好跨进下一档,是整段唯一肉眼可见的形变。
- 成本:纯算术,render 无增量;整段蹦跳最多多出 1~2 张变形网格(缓存 12 张)。
  **保留**。

### E24 · 本轮评估后否决的动态感方案(2026-09-17,未实施)
- **待机呼吸挤压(squash 随呼吸 ±1%)**:变形缓存键按 1/12 分档,±1% 永远
  跨不过档,画不出来;幅度大到跨档则每次跨档都是一次网格未命中
  (单次约 21ms,待机一帧总共才约 13ms)。否决。
- **发丝飘动**:需要按帧改头发区域的网格变形,同样打穿变形缓存。深度模型
  里头发已有约 260ms 的滞后跟随。否决。
- **命中时整窗小闪光**:分层窗口是透明的,整窗叠一层白会在她周围亮出一个
  矩形边框;全画布合成每帧约 2~3ms。改用落点处的命中光环(E21)。否决。
- **新特效走 LightLayer 加色光层**:每次 add 是一次 ImageChops.add 逐像素
  运算,违反"帧循环只贴图"。新特效一律直接贴预渲染精灵。否决。
- **抛飞速度线(矢量线拖尾)**:能在高速时补足 E27 的弱点,当时记为候选
  —— 第三批已实现,见 E29。
- **环境光随时段变色**(清晨金/白天蓝/黄昏橙/深夜紫,改法阵底光颜色):
  零成本,但法阵底光只有 60 透明度,换色后肉眼几乎分不出;列入候选未选。
- **插电充能特效加层次**:触发极少(只在插电那一下),收益低;未选。



### E18 · 深度网格 numpy 向量化(评估否决,未实施)
- 目的:跳舞时 `mesh`/`displacement`/`_has_ink` 每帧约 3ms 纯 Python 计算

- 否决:任何 numpy 依赖都会让进程多约 490MB 提交内存(见 E15 教训),

### E11 · 旋转演出提速(实测否决,未上线)
- 假设:twirl/transform/roll 的每帧 `rotate+expand+缩回`(2x 画布实测
  ~72ms/帧)可以优化:①按角度分档缓存旋转结果;②先 reduce 到 1x 旋转
  再放大回 2x。
- 实测否决:①回转类动作的角度都是**单调扫过**(720° 转一圈不回头),
  分档缓存首播命中率是零,而 120 个角度档 × 4MB 一张,内存爆炸;
  ②"1x 旋转再放大"实测 64.9ms vs 现状 71.6ms —— 收益被放大回 2x 的
  一步吃光(9%,噪声级)。
- 现状兜底:旋转期间 `tick` 的自适应本来就按单帧耗时把 60fps 降到
  30fps,快速运动下足够顺滑。
- 决定:**放弃**。旋转的成本是内在的,除非换 GPU/着色器路线,别再试
  缓存或降分辨率路线。
